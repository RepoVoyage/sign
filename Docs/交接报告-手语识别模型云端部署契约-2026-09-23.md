## 2. 为什么传 H.264 原流而不是像素（带宽硬约束）

- 手机连相机时进程绑定相机热点（热点**无互联网**），公网只有蜂窝一条路
  （ARCHITECTURE §2.4.7，已真机验证双网并发）。
- 解码后 I420 裸像素 640×384@30 ≈ **10.6 MiB/s**——蜂窝不可行。
- 相机原始 H.264 码流实测 ≈ **4 Mbps**——LTE/5G 可行。
- 结论：App **转发原始压缩流，不解码不重编码**（ARCHITECTURE §2.2.3"只解码不为
  模型重新编码"的精神：云端拿到的与相机产出比特一致）；**云端自行解码并按
  ModelSpec 做与训练一致的预处理**（crop/mirror/归一化/重采样规则以队友的
  ModelSpec 为准，App 不代做）。

## 3. 流事实（真机实测，云端解码器必须容忍）

| 事实 | 数值/说明 |
|---|---|
| 编码 | H.264，30fps，无音频 |
| 分辨率 | **声明 1920×1080，实际编码 640×384**（5:3 鱼眼）；以 SPS 为准，不要信会话参数 |
| CSD | SPS/PPS 共 61 字节随流首发；开流后约 2s 出首帧 |
| GOP | **超长（>1000 帧）**：4.5 分钟仅 2 个自然 IDR。云端解码只能依赖 App 随会话送出的 CSD+首个同步帧起步；不要等"下一个 IDR" |
| 同步帧保证 | App 从参数集+随机访问点开始转发（复用已验证的 `DecodeSyncGate` 门控逻辑的上游版本） |
| gyro | 不转发 |

## 4. 传输与上行格式（App → 云）

- 传输：**WSS**（TLS WebSocket），一个会话一条连接；`Authorization: Bearer <token>`
  握手头（token 发放方式由部署侧定，App 设置页将增加对应凭据项，随 P6 适配器落地）。
- **首条消息（text 帧，JSON）**——会话初始化：

```json
{
  "proto": 1,
  "type": "SESSION_INIT",
  "sessionId": "uuid-…",
  "streamGeneration": 7,
  "modelId": "model-a | model-b",
  "media": { "codec": "H264", "packing": "length-prefixed-au", "fps": 30 },
  "clientInfo": "yuqiao-android/0.1.0"
}
```

  `modelId`：用户在 App 设置页选择（模型 A=面对面视角 / 模型 B=第一视角），
  服务侧据此路由；两模型**共用本契约**。

- **后续 binary 帧**——H.264 访问单元，前缀 13 字节定长头（大端）：

```text
+-------------------+------------------+---------+---------------------------+
| uint64 ptsUs(µs)  | uint32 payloadLen| uint8 flags | H.264 AU payload        |
+-------------------+------------------+---------+---------------------------+
flags: bit0 = keyframe(IDR)   bit1 = 含参数集(SPS/PPS)   其余保留为 0
```

  `ptsUs` = 相机媒体时间（单调，µs），与 `streamGeneration` 共同唯一。

- **控制消息（text 帧，JSON）**：

| type | 方向 | 字段 | 语义 |
|---|---|---|---|
| `GAP_EVENT` | App→云 | `reason`(LOST_FRAMES\|DECODE_RESET\|RECONNECT\|OVERLOAD), `lastPtsUs` | 缺帧/重置：云端不得跨 GAP 拼接时序上下文 |
| `EPOCH_RESET` | App→云 | `sequenceEpoch`(新值) | 重连/中断：云端丢弃旧 epoch 未回推理（= §4.1 `resetSequence` 语义） |
| `HEARTBEAT` | 双向 | `t`(单调 ms) | 2s 间隔；6s 无任何完整消息即双方断开会话 |
| `END` | App→云 | `reason` | 用户停止；云端收尾并释放会话资源 |

## 5. 下行格式（云 → App，text 帧 JSON）

逐字段对应 API.md §4.1 `RecognitionUpdate`（App 侧零转换直送段状态机）：

```json
{
  "proto": 1,
  "type": "RECOGNITION",
  "sequenceEpoch": 7,
  "segmentId": null,
  "draftText": "我需要帮助",
  "confidence": 0.82,
  "tokenSpans": [ { "text": "我", "startPtsUs": 1000000, "endPtsUs": 1400000, "stable": true } ],
  "boundary": {
    "cutoffPtsUs": 3500000,
    "requiredFutureContextUs": 500000,
    "reliability": "RELIABLE",
    "source": "MODEL"
  }
}
```

- `segmentId`：null = 开新段（App 生成 id）；模型自带稳定 id 亦可（跨更新同段=修订）。
- `draftText`：去重标签后的草稿；同段后续更新即修订（App 侧 revision 自增）。
- `boundary`：**自动边界信号，发布门槛**（§4.2）——`RELIABLE` 触发 App 收尾冻结
  （2s 窗口）；`UNCERTAIN` 转人工核对不阻塞后续。**不得**用固定静默时长或 LLM
  补标点替代真实边界能力；随模型交付验证集误切/漏切率。
- `tokenSpans`：模型支持则给（字幕级时间锚点），不支持传 null。
- 频率与延迟预算：草稿 ≥2 Hz；边界判定在 cutoff 证据齐备后 ≤300ms 内发出
  （端到端 p95<2s 的总预算含 App 2s 收尾 + LLM，见 §7）。
- 错误：`{"type":"ERROR","code":"MODEL_NOT_READY|DECODE_FAILED|OVERLOAD|…","message"}`
  → App 显示"识别不可用"，**不伪造文本**（§6 错误矩阵）。

## 6. 会话/代次/时间语义

- `sessionId + streamGeneration` 唯一标识一路流；重连 = 新 generation，云端按
  `sessionId` TTL 清理旧会话资源。
- `ptsUs` 为相机媒体时间，**不是手机墙钟**；跨 generation 不保证连续。
- 旧 epoch 的迟到事件 App 直接丢弃（§5.2 规则），云端亦应在 `EPOCH_RESET` 后停发。

## 7. 验收指标（发布门槛，ARCHITECTURE §7/§8）

| 指标 | 门槛 |
|---|---|
| 边界判定+草稿延迟 | ≤500ms（p95），给 App 2s 收尾 + LLM 留预算，合起来端到端 p95<2s |
| 自动边界误切/漏切率 | 随模型交付验证集数字；未经验证**不得**接连续翻译发布路径 |
| 30 分钟持续流压测 | 事件零丢失、零乱序、内存平稳 |
| 双模型一致性 | A/B 共用契约，仅 `modelId` 路由不同 |
