# P6 App 侧对接契约（基于《安卓联调手册 v0》，2026-09-23）

> 依据：`Docs/安卓联调手册_2026-09-23.md`（识别服务已建成并 17/17 验收）。
> **修订说明**：`Docs/交接报告-手语识别模型云端部署契约-2026-09-23.md` 中的
> WSS+H.264 原流方案**作废**，以手册 v0 的 HTTP JPEG 接口为准（服务已按此实现）。
> 本文定义 App 侧（本仓库 P6 适配器）的实现契约与语义映射。

## 1. 链路与帧来源

```
SdkCameraSession 解码帧(I420 640×384@30)
  → 降采样 @10fps（每 3 帧取 1）
  → YuvImage.compressToJpeg(q85) → base64
  → POST /v1/sign/frame {"session_id","ts","jpeg_b64"[,"flush"]}
  → events → EventMapper → RecognitionUpdate → SentenceManager（既有）
```

- 带宽：JPEG q85@640×384 ≈ 40–60 KB/帧 × 10fps ≈ **0.4–0.6 MB/s**——蜂窝可行
  （双网并发已验证）。解码复用既有 `SurfacelessH264Decoder`，不新增解码器。
- 仅管线 RUNNING 且识别服务 health 通过时送帧。

## 2. 会话与时间基

- `session_id` = `<appSessionId>-g<streamGeneration>`；重连新代次 = 新 session_id，
  并对旧 session_id 主动 `POST /v1/sign/reset`。
- **`ts` = 帧 ptsUs / 1e6（相机媒体时间）**——手册允许"相机帧时间戳"；由此服务端
  回传的 `seg_start/seg_end/stream[].start/end` 全部为媒体时间基，可直换 ptsUs，
  与 §5.2 数据契约的媒体时间语义一致（不混墙钟）。

## 3. 事件 → 领域映射（EventMapper）

每个 event = 一个已收尾段（停顿腕速静止 ≥0.4s 产出）：

```kotlin
RecognitionUpdate(
  sequenceEpoch = streamGeneration,
  segmentId     = "seg-" + seg_start,            // 同段重发=修订（服务侧一般一次）
  draftText     = sentence_candidate,
  tokenSpans    = stream.map { TokenSpan(it.word,
                      (seg_start + it.start) * 1e6.toLong(),
                      (seg_start + it.end)   * 1e6.toLong(), stable = true) },
  confidence    = sentence_confidence,           // 组合 LLM 的句子置信度（事件新增字段，见下）
  boundary      = BoundarySignal(
                    cutoffPtsUs = seg_end * 1e6,
                    requiredFutureContextUs = 0, // 事件已在段尾产出
                    reliability = RELIABLE,      // CV 侧不确定由组合 LLM 消化；降级见下
                    source = MODEL),
)
```

- **置信度流程（2026-09-23 用户定稿）**：CV 侧每动作出多候选+CV 置信度 →
  **服务侧**送组合 LLM 挑词成句并给出 `sentence_confidence` → App 只消费句子+
  句子置信度。`sentence_confidence < 0.7`【初始值，用户定】→ 管线降级
  UNCERTAIN → 待核实标志 + 震动（识别侧唯一触发情形）；guard 保真失败与其
  **同桶**（用户确认）。阈值后续随校准集/ModelSpec confidenceCalibration 调整。
- `needs_repeat=true`（margin<0.03，约 6% 请求）：**重打提示**瞬态文案
  "请重打一次该句"（非待核实标志、不震动）；不冻结不播报。
- `stream` 中 `word="待确认动作"` 原样进入 tokenSpans 文本。
- **收尾窗口**：识别服务事件自带段尾证据，管线 `finalizeDelayMs` 在识别服务
  模式降为 **500ms**（桩源模式保持 2s）——§5.1 的 2s 是【初始值】可调。

## 4. LLM 阶段决策（v0）

- `sentence_candidate`（闭集还原句）**直接作为 rawChinese** 进入既有
  `LanguageProcessor`（保真提示词 + 整理 + 翻译 + guard）。
- 队友仓库的百炼闭集还原 prompt（CLOSED）**暂不接**：候选已是完整句；若验收期
  自然度不足，再议服务侧内嵌或共享 prompt。

## 5. 模型 A/B 与 health

- 手册 v0 服务为单模型；设置页"模型 A（面对面）/模型 B（第一视角）"选择**保留但
  暂不下发**，待服务支持双视角路由后于 frame 会话首包扩展 `model` 字段。
- 启动前 `GET /v1/sign/health` 校验 ok/model；失败 → 界面"识别服务不可用"
  （§6 错误矩阵：不伪造文本），5s 重试。

## 6. 错误与重连

- 帧 POST 连续 3 次失败/超时（1s/帧）→ 停送帧 + "识别服务不可用" + health 轮询恢复。
- 流 GAP（解码重置/重连）→ 新代次新 session_id（=服务端 reset 语义），不跨代拼接。

## 7. 延迟预算对账（§7 口径）

事件（停顿后 ~0.5s）+ 收尾窗口 0.5s + LLM 整理/翻译（实测 1–2s）≈ **2–3s/句**。
ARCHITECTURE §7 的 p95<2s 为待验收目标：瓶颈在 LLM 阶段，验收期实测记录，
不承诺即达标；识别侧（事件 ≤0.5s）已满足手册预算。

## 8. App 侧任务清单（P6 实现）

1. `SignStreamClient`：OkHttp 逐帧 POST + base64 + flush/reset/health
2. `FrameSampler`：解码帧 @10fps 抽样 + JPEG q85（training/production 共用）
3. `EventMapper`：§3 映射（纯函数，单测覆盖：needs_repeat/low_conf/词跨度换算）
4. `RecognitionSourceImpl`（production）：由"不可用"换为真客户端；training 桩源保留
5. 管线接线：识别服务模式 finalizeDelayMs=500ms；字符串（重打提示等）
6. 验收：17 句真机各 1 段字幕=句名；needs_repeat 句显示重打提示；gen2 零串扰；
   蜂窝送帧带宽实测
