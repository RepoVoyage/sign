# 随心说五句演示：App 接入交接

更新时间：2026-09-23。公网服务已部署并通过真实视频联调。详细字段、错误码和旧翻译接口见 [完整 API 文档](API.md)。Agent 的机器可读定义是 [OpenAPI](openapi.json)；CV 服务暂按 API.md 中的人工契约对接。

## 当前能做什么

链路为：GO 3S → App 取得并**切好一个词的 MP4** → CV `/v1/recognize` 返回最多三个词候选 → App 按顺序汇集一个句子段的候选 → Agent `/v1/compose-signs` 从五句固定语料中选择 → App 展示供用户确认。当前没有连续视频自动切词、切句、拒识或自动播报。`/v1/polish` 是原有的已确认文本整理/翻译接口，可独立使用；五句补全无需再调用它。

公网基础地址 `https://101.37.234.129`，保留 HTTPS 证书验证。手机只访问 443；8000 与 8765 是服务器本机端口。两个 POST 使用不同令牌：CV 的 `CV_SERVICE_TOKEN` 保存在服务器 `/opt/insta360-cv/.env`，Agent 的 `SERVICE_API_KEY` 保存在服务器 `/opt/insta360-agent/.env` 和维护者本机 `agent/.env`。令牌由维护者私下交给 App 开发者，不写入 GitHub、截图或公开构建；服务器登录密码不是 API 令牌。

## App 对接顺序

1. 为一次沟通建立 `sessionId`（UUID）；给当前句子段分配 `segmentId` 和 `revision`。App 保留视频切分、词序、句子边界及代次状态。
2. 每切出一个孤立词 MP4，按原始视频字节发 `POST /v1/recognize`，头部为 `Content-Type: video/mp4`、`Authorization: Bearer <CV_SERVICE_TOKEN>`。单片段 ≤32 MiB。`status=OK` 时保留返回 `candidates` 的**原有顺序**；`TOO_SHORT` 或 `INSUFFICIENT_HAND_DETECTION` 时提示重做该动作，不补一个假词。
3. 当前句子结束后，把每个词的 `candidates` 按拍摄顺序放进 `gestures`，发 `POST /v1/compose-signs`。头部为 `Content-Type: application/json`、`Authorization: Bearer <SERVICE_API_KEY>`。可加 `X-Remaining-Budget-Ms`（1–10000），但 App 自己仍需管理整个请求的截止时间。
4. 仅 `status=CANDIDATE` 且 `sentence` 非 null 时展示该句及 `alternatives`，让用户确认。`AMBIGUOUS` 或 `INSUFFICIENT_EVIDENCE` 显示“无法确定，请重试/手动输入”。`needsConfirmation` 恒为 true；不可直接 TTS。
5. 收到响应先核对请求快照的 `sessionId`、`segmentId`、`revision`、视频流代次和当前设置。断流、停止、用户重录或句段修订后，旧结果不得覆盖当前界面。确认后是否播报由 App 决定。

CV `score` 是未校准 softmax，不是正确率或可靠概率。`any_hand_fraction` 只说明多少帧检测到手，也不是正确率。网络或网关错误可能不是 JSON，先检查 HTTP 状态和 Content-Type。CV 的错误是简单 `{"error":"..."}`；Agent 错误是 `{"segmentId":...,"revision":...,"error":{"code":...,"message":...,"retryable":...}}`。

## 用已有视频快速试一次

维护者可通过 `ssh ecs-user@101.37.234.129` 登录后查看 `/opt/insta360-cv/.env` 获取 CV 令牌；Agent 令牌可从本机 `agent/.env` 的 `SERVICE_API_KEY` 获取。不要把令牌值粘贴进共享文档。在项目根目录、自己的终端设置两枚令牌：

```bash
export CV_SERVICE_TOKEN='从服务器 /opt/insta360-cv/.env 获取'
export SERVICE_API_KEY='从 agent/.env 获取'

python3 agent/tools/demo_pipeline.py \
  cv/data/videos/session04/我1.MP4 \
  cv/data/videos/session04/回1.MP4 \
  cv/data/videos/session04/家1.MP4
```

这个脚本逐个上传视频，输出三次 CV 候选，并自动把实际候选组成 Agent 请求，最后打印候选句；它不会在输出中打印令牌。若想单独检查接口，可用下面的 cURL：

```bash
curl --fail-with-body --max-time 60 \
  -H "Authorization: Bearer ${CV_SERVICE_TOKEN}" \
  -H 'Content-Type: video/mp4' \
  --data-binary @cv/data/videos/session04/我1.MP4 \
  https://101.37.234.129/v1/recognize
```

对“回1”“家1”各重复一次，保留三次 `candidates`。然后把真实候选按顺序填入下面的 JSON 并请求 Agent；示例数值只是字段写法，不能替代 CV 实际返回：

```json
{
  "sessionId": "12345678-1234-1234-1234-123456789abc",
  "segmentId": "manual-test-1",
  "revision": 1,
  "gestures": [
    {"candidates": [{"label": "我", "score": 0.8}]},
    {"candidates": [{"label": "回", "score": 0.7}]},
    {"candidates": [{"label": "家", "score": 0.6}]}
  ]
}
```

将 JSON 保存为本地 `request.json` 后运行：

```bash
curl --fail-with-body --max-time 15 \
  -H "Authorization: Bearer ${SERVICE_API_KEY}" \
  -H 'Content-Type: application/json' \
  --data-binary @request.json \
  https://101.37.234.129/v1/compose-signs
```

五句目标及其主要 CV 词序：

| 目标句 | CV 词标签序列 | 补全说明 |
|---|---|---|
| 我想回家 | 我、回、家 | “想”没有单独训练，由固定句式补出 |
| 你一定可以 | 你、一定、可以 | 原词组合 |
| 你要照顾好自己 | 你、要、照顾、好、自己 | 原词组合 |
| 祝大家新年好 | 祝贺、大家、新、年、好 | “祝贺”映射到固定句的“祝” |
| 我们只是好久不见 | 我们、只、是、很久不、见 | “很久不”映射到“好久不” |

候选不足或语义冲突时返回 null；模型只能选上述五句，不生成自由文本。App 若要扩大语料，需同步 CV 标签、Agent 语料和独立测试集。

## 已验证的联调结果与边界

公网 HTTPS 上传 `session04` 的“我1”“回1”“家1”三个**已切好的**视频，CV 首候选依次为我、回、家。把三次真实前三候选原样提交 Agent，返回 HTTP 200、`sentence="我想回家"`、`needsConfirmation=true`。收紧弱候选过滤后，两个排名第三的词不会单独让无关句子进入备选。旧 `/v1/polish` 在同一公网入口也返回 HTTP 200。

这只是选定片段的一次端到端连通性验证，不是五句准确率。CV 的 session04 同场次随机留出为 13/19 正确，且缺少新场次、非目标动作及多用户测试；上线前不能以此作为自动播报依据。
