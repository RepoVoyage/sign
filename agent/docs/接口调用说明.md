# 随心说 Agent 接口调用说明

版本：2.1.0 ｜ 更新日期：2026-09-23 ｜ 面向：Kotlin App、Apifox 测试及团队联调

## 五句手语演示：POST /v1/compose-signs

这是新增的本地实现接口。App 将一个句子段内各手势的 CV 前三候选按时间顺序提交；服务只在预设五句中选择，或返回 null。**当前线上地址是否已有此接口，须查看线上 `/openapi.json` 确认；本地代码完成不等于已部署。**完整字段和限制见 [API.md](API.md#0-五句手语演示接口post-v1compose-signs)。

```json
{
  "sessionId": "12345678-1234-1234-1234-123456789abc",
  "segmentId": "seg-sign-1",
  "revision": 1,
  "gestures": [
    {"candidates": [{"label": "我", "score": 0.82}, {"label": "我们", "score": 0.12}]},
    {"candidates": [{"label": "回", "score": 0.71}]},
    {"candidates": [{"label": "家", "score": 0.63}]}
  ]
}
```

返回的 `sentence` 是五句之一或 null，`alternatives` 是有最低词序证据的可选句，`status` 表示 `CANDIDATE` / `AMBIGUOUS` / `INSUFFICIENT_EVIDENCE`；`needsConfirmation` 恒为 true。App 应让用户确认，不能直接播报。认证头与下文 `/v1/polish` 相同。CV 只识别孤立词，连续视频切词和切句仍需 App 处理。

本接口接收一句已经结束并冻结的中文识别原文，进行语句整理和按需翻译。接收文本，不接收视频、图片或单词事件。以下请求和返回内容仅用于解释协议，实际结果由模型生成。

## 1. 服务地址

| 用途 | 地址 | 是否需要令牌 |
|---|---|---|
| 整理与翻译 | `POST https://101.37.234.129/v1/polish` | 是 |
| 健康检查 | `GET https://101.37.234.129/health` | 否 |
| 在线调试文档 | https://101.37.234.129/docs | 打开文档不需要，调用翻译需要 |
| OpenAPI 定义 | https://101.37.234.129/openapi.json | 否 |

所有调用直接使用 HTTPS。旧接口 `/api/v1/compose` 已移除。

## 2. 认证和请求头

访问令牌由服务维护者单独提供，对应配置名 `SERVICE_API_KEY`。它不同于模型供应商的 `LLM_API_KEY`，也不是服务器登录密码。不要将真实令牌写入共享文档、代码仓库或请求截图。

| 请求头 | 必填 | 值 |
|---|---|---|
| Authorization | 是 | `Bearer <访问令牌>`，Bearer 后有一个空格，不保留尖括号 |
| Content-Type | 是 | `application/json` |
| X-Remaining-Budget-Ms | 否 | 剩余处理预算，整数 1–10000，单位毫秒，默认 10000 |

例如：

```http
POST /v1/polish HTTP/1.1
Host: 101.37.234.129
Authorization: Bearer <访问令牌>
Content-Type: application/json
X-Remaining-Budget-Ms: 10000
```

Apifox 选择「认证 → Bearer Token」，仅粘贴令牌值，不再手动加 `Bearer `；工具会生成请求头。缺少或错误的令牌返回 HTTP 401。

## 3. 请求体

### 3.1 完整示例

```json
{
  "sessionId": "12345678-1234-1234-1234-123456789abc",
  "segmentId": "seg-1",
  "revision": 1,
  "rawChinese": "我 需要 帮助",
  "targetLanguages": ["zh-CN", "en-US"],
  "context": []
}
```

### 3.2 字段说明

| 字段 | 类型 | 必填 | 规则 |
|---|---|---|---|
| sessionId | string | 是 | UUID 字符串；一次会话一个 ID，同一会话内复用 |
| segmentId | string | 是 | 本次句子/段的标识，1–128 字符，非纯空白；会话内唯一 |
| revision | integer | 是 | 本段修订号，0–2147483647；不得传字符串、浮点数或布尔值 |
| rawChinese | string | 是 | FINAL 冻结的识别原文，1–2000 字符，非纯空白；不是 words 数组 |
| targetLanguages | string[] | 否 | 默认 `["zh-CN"]`；1–8 项，不得重复 |
| context | object[] | 否 | 默认 `[]`；最多 5 条已确认历史句子，仅用于有限衔接 |
| context[].segmentId | string | context 中必填 | 历史句子的段标识，1–128 字符，非纯空白 |
| context[].rawChinese | string | context 中必填 | 历史已确认原文，1–2000 字符，非纯空白 |

请求及 context 项不接受未约定的额外字段。rawChinese 按原样输入模型，不自动删除空格、拆词或去重。是否属于 FINAL、上下文是否已经确认，由 App 保证。

语言标签示例：`zh-CN`（中文）、`en-US`（英语）、`ja-JP`（日语）。暂接受“小写 2–3 字母语言 + 可选首字母大写的 4 字母脚本 + 可选大写 2 字母或 3 位数字地区”，例如 `zh-Hant-TW`。`en_US` 不合法。格式合法不代表模型一定能够完成该语言。

上述长度/数量上限是当前实现的保护性约定，不代表已经完成真机性能验收。

### 3.3 仅整理中文

```json
{
  "sessionId": "12345678-1234-1234-1234-123456789abc",
  "segmentId": "seg-2",
  "revision": 1,
  "rawChinese": "厕所 哪里",
  "targetLanguages": ["zh-CN"]
}
```

此时不生成外语，返回的 `translations` 应为 `{}`。

### 3.4 携带已确认上下文

```json
{
  "sessionId": "12345678-1234-1234-1234-123456789abc",
  "segmentId": "seg-3",
  "revision": 1,
  "rawChinese": "请 帮助 我",
  "targetLanguages": ["en-US"],
  "context": [
    {"segmentId": "seg-1", "rawChinese": "我 需要 帮助"}
  ]
}
```

服务端不存储会话上下文，历史内容需要调用方显式提交。上下文不能用来给当前句子新增事实。

## 4. HTTP 200 返回

### 4.1 整理与翻译成功

```json
{
  "polishedChinese": "我需要帮助。",
  "translations": {
    "en-US": "I need help."
  },
  "issues": [],
  "segmentId": "seg-1",
  "revision": 1
}
```

| 字段 | 类型 | 含义 |
|---|---|---|
| polishedChinese | string / null | 整理后的中文，非空时最长 2000 字符；未完成则 null |
| translations | object | 语言标签到译文的映射，每条非空且最长 2000 字符；不含 zh-CN，只含请求的其他语言 |
| issues | object[] | 每种语言的歧义、保真或不可用标记；没有问题时为空数组 |
| segmentId | string | 原样返回请求的段标识 |
| revision | integer | 原样返回请求的版本号 |

中文结果单独放在 `polishedChinese`，不是 `translations["zh-CN"]`。即使只请求外语，也可能返回中文整理结果，但 App 只应展示/播报用户选择的语言。

响应没有顶层 `status`、`sentence`、`question` 或 `sessionId`。客户端通过本次请求快照关联 sessionId 和其他代次信息。

### 4.2 某个语言未完成

请求了中文、英文和日文，但日文未完成时：

```json
{
  "polishedChinese": "我需要帮助。",
  "translations": {
    "en-US": "I need help."
  },
  "issues": [
    {
      "language": "ja-JP",
      "code": "UNAVAILABLE",
      "message": "该语言翻译未完成。"
    }
  ],
  "segmentId": "seg-1",
  "revision": 1
}
```

保留已有的中文/英文结果；日文不可用，不能拿中文冒充日文。未完成的外语键被省略，不返回空字符串。

### 4.3 结果需要核对

```json
{
  "polishedChinese": "我需要帮助。",
  "translations": {},
  "issues": [
    {
      "language": "zh-CN",
      "code": "AMBIGUITY",
      "message": "原意存在歧义，请核对候选句。"
    }
  ],
  "segmentId": "seg-4",
  "revision": 1
}
```

示例表示候选句需要人工核对，不应仅因为 HTTP 200 就自动播报。

### 4.4 issues 字段与状态判断

| 字段 | 类型 | 说明 |
|---|---|---|
| language | string | 受影响的语言，中文整理使用 zh-CN |
| code | string | 下表三个枚举之一 |
| message | string | 非空说明，最长 300 字符 |

| code | 客户端状态 | 处理方式 |
|---|---|---|
| AMBIGUITY | NEEDS_CONFIRMATION | 原意存在歧义，展示候选供核对，不自动 TTS |
| FIDELITY_CHECK_FAILED | NEEDS_CONFIRMATION | 可能改变否定、数字或重复等含义，不自动 TTS |
| UNAVAILABLE | UNAVAILABLE | 无可用结果；中文为 null，外语省略对应键 |

对每个选定语言分别判断：

1. 缺少对应文本，或有 UNAVAILABLE → UNAVAILABLE。
2. 文本存在，但有其他 issue → NEEDS_CONFIRMATION。
3. 文本存在且无对应 issue → READY。

优先级为 `UNAVAILABLE > NEEDS_CONFIRMATION > READY`。无 issue 并不等于所有语义都已验证正确；当前规则不能证明跨语言翻译准确性。

## 5. 错误响应

错误通过 HTTP 状态码和 `error` 对象表示，结构与 200 响应不同。

### 5.1 令牌错误：HTTP 401

```json
{
  "segmentId": null,
  "revision": null,
  "error": {
    "code": "UNAUTHORIZED",
    "message": "请提供有效的服务访问令牌。",
    "retryable": false
  }
}
```

### 5.2 模型超时：HTTP 504

```json
{
  "segmentId": "seg-1",
  "revision": 1,
  "error": {
    "code": "MODEL_TIMEOUT",
    "message": "期限内未完成，请将未返回语言标记为 UNAVAILABLE。",
    "retryable": true
  }
}
```

### 5.3 错误码表

| HTTP | error.code | retryable | 建议操作 |
|---|---|---|---|
| 401 | UNAUTHORIZED | false | 检查 Bearer 格式及服务访问令牌 |
| 422 | INVALID_REQUEST | false | 检查 JSON、UUID、字段类型、语言标签、长度及预算头 |
| 503 | MODEL_NOT_CONFIGURED | false | 联系维护者补齐模型配置 |
| 504 | MODEL_TIMEOUT | true | 当前未完成语言标不可用，按用户操作/剩余期限决定重试 |
| 502 | MODEL_UNAVAILABLE | true | 上游网络异常，可稍后重试 |
| 502 | MODEL_AUTH_FAILED | false | 维护者检查模型供应商密钥，不是 App 令牌错误 |
| 503 | MODEL_RATE_LIMITED | true | 模型供应商限流，稍后重试 |
| 502 | MODEL_UPSTREAM_ERROR | 上游 5xx 为 true，其他 false | 模型供应商返回异常状态 |
| 502 | MODEL_INVALID_RESPONSE | true | 模型返回格式不符合协议 |
| 500 | INTERNAL_ERROR | false | 联系维护者检查日志 |

401、422、500 的关联字段为 null，客户端使用请求快照关联。其他已处理模型错误会回传合法的 segmentId/revision。

网关还可能返回 **413（请求体超过 128 KiB）**、**429（服务访问限流）**，也可能出现网络断开等无响应情况。网关错误不保证是 JSON，不应直接强行反序列化为成功对象。错误路径/方法的 404/405 使用框架默认格式。

`retryable=true` 表示技术上可以重试，不表示必须立即重试，也不能绕过手机原截止时间或复活过期任务。服务端不自动重试模型请求。

## 6. Apifox 调用步骤

1. 新建 HTTP 请求，方法 POST，URL 填 `https://101.37.234.129/v1/polish`。
2. 认证选择 Bearer Token，粘贴维护者提供的访问令牌。
3. Body 选择 JSON，复制第 3.1 节请求体。
4. 确认 Content-Type 为 application/json，发送请求。
5. 检查 HTTP 状态码；200 再检查每种语言的 issues，非 2xx 读取 error 或网关提示。

也可导入 `https://101.37.234.129/openapi.json`，并在 Apifox 将服务基础地址设置为 `https://101.37.234.129`。令牌需自行配置，不包含在 OpenAPI 中。保留 HTTPS 证书验证，不需要关闭 SSL 校验。

## 7. cURL 调用

先在自己的终端设置服务令牌环境变量；下面的占位内容须替换为维护者提供的令牌，不要将真实值保存进共享脚本：

```bash
export SERVICE_API_KEY='替换为维护者提供的访问令牌'

curl --max-time 15 --request POST \
  'https://101.37.234.129/v1/polish' \
  --header "Authorization: Bearer ${SERVICE_API_KEY}" \
  --header 'Content-Type: application/json' \
  --header 'X-Remaining-Budget-Ms: 10000' \
  --data '{
    "sessionId": "12345678-1234-1234-1234-123456789abc",
    "segmentId": "seg-1",
    "revision": 1,
    "rawChinese": "我 需要 帮助",
    "targetLanguages": ["zh-CN", "en-US"],
    "context": []
  }'
```

这里的 15 秒是人工接口测试客户端等待时限；App 的业务期限应按下一节处理。

## 8. App 对接注意事项

- 一次请求提交一个 FINAL 原文。新段使用新 segmentId，同段内容修订增加 revision。
- 服务不保存历史或自动去重；相同请求再次提交可能再次调用模型。
- 请求发出时保留 sessionId、streamGeneration、sequenceEpoch、segmentId、revision、settingsRevision 快照。响应回来先确认快照仍有效，再展示结果。
- 断流、停止或设置改变后，旧结果应丢弃；不能只核对 revision 而忽略会话/代次/设置。
- 仅 READY 且属于用户选定播报语言的结果才能进入后续 TTS 流程；仍需遵守 App 段状态和播报去重规则。
- 云端模型调用最多 10 秒，所有语言共享期限；可通过 X-Remaining-Budget-Ms 缩短，但不可延长。
- App 必须从 FINAL 开始用手机单调时钟计算总期限，包含排队和网络；不要将手机绝对单调时间直接传给服务器比较。
- 当前响应是一次性 JSON，不是流式；全请求超时不能得到尚未交付的部分语言，但不能撤销其他有效请求已有的结果。
- 当前按来源 IP 限制平均 30 次/分钟，允许突发 5 次，同一 IP 最多 3 个并发请求；同一出口网络下的设备共享限额。

## 9. 健康检查

```http
GET https://101.37.234.129/health
```

不需要认证，返回 HTTP 200：

```json
{
  "status": "ok",
  "model_configured": true
}
```

`status=ok` 表示服务可以响应；`model_configured=true` 只说明模型配置已填齐，不证明模型供应商当前可用，也不证明每次请求都能在 10 秒内完成。
